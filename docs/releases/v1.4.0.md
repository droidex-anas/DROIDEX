## What’s new

- Run a chat on Claude Code or Codex as well as Droid. Pick the harness before the first prompt and the chat stays on it: streaming, reasoning, tool rows, approvals, questions, Stop, steering, model and effort changes, and resume after a restart work on all three. The sidebar marks each chat with its harness.
- Each harness brings its own commands, skills, plugins and apps into the composer’s slash and @ menus, with their real icons.
- Model and effort are remembered per chat. Switching model shows a notice naming both models, and a harness usage limit shows a quiet notice with the reset time instead of an error.
- A new model picker lists models and drills into an effort slider for the selected one. The classic list stays available in Settings.
- One agent card follows subagents from every harness: Droid subagents, Claude Code tasks and workflows, and Codex delegation. It docks above the composer while agents run, and any agent opens in the side panel with its own conversation.
- Schedule a prompt into a conversation you already have. Scheduled prompts wait above the composer with their send time, can be cancelled there, and are listed in Automations under a Scheduled prompts filter. Scheduling lives in the draft’s right-click menu.
- Redesigned utility and files panes, with a collapsible tree and a file preview. Running processes sit in the chat header.
- Copy Session ID copies the id the harness’s own CLI resumes by, and names its command.
- Faster sidecar start, a lighter initial bundle, and many fixes: GitHub check status no longer reads passed while a check is still queued, file paths with spaces or Windows separators become links, the model popover fits narrow windows, and light themes get accessible status colours on every preset.
- DROIDEX is now open source under the Apache License 2.0.
- Packaged builds count installations anonymously: a random id and two events (app opened, first launch), with no content, account or hardware data. Turn it off under **Settings → Privacy & diagnostics**.

## Updating from 1.3.0

DROIDEX 1.4.0 keeps the existing application identity, Sparkle signing key,
architecture-specific update feeds, user-data location, session store, settings,
workspaces, automations store, and raw Factory session history unchanged.
Claude Code and Codex transcripts, per-chat model settings and scheduled prompts
are stored alongside them in the app’s data directory. Claude Code and Codex
use their own installed CLIs and sign-ins; DROIDEX does not change their
configuration.

Update checks may run in the background, but DROIDEX does not download or
install updates automatically. Use **DROIDEX → Check for Updates…** or the blue
update button beside Settings, then approve the update and relaunch. The native
updater waits for the app and sidecar to settle before installing.

The macOS artifacts are ad-hoc signed, so a manual DMG install may require
approval in **System Settings → Privacy & Security** on first launch.
