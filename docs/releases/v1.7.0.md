## What's new

- **Design systems are documents.** Click the design system chip in a Design chat and the kit opens in place of the board, beside the chat, with a cover, notes and typed token tables for colours, typography, spacing, corner radius, shadows and motion. A section nav with search and counts keeps a large kit easy to read, and Back to board returns you to the same view and selection.
- **Edit a kit where you read it.** Click a value to change it, pick a colour from its swatch, split a token into light and dark values, give a token a usage note, or add a note of your own. Live previews follow every edit before you save, and unsaved changes are marked until you do.
- **Every save is a version.** The version menu lists each version with what it changed and when. Open an older one and restore it as the next version. If a version was saved while you were editing, nothing is overwritten: you choose between your edits and the saved ones. Every canvas that uses the kit moves to the new version, and requests already queued keep the one they started with.
- **The agent proposes, you decide.** Ask the agent to change one of your kits and it makes a proposal, not a new version. Review shows the proposed changes with the same marks as your own edits, then Accept or Discard. Kits the agent creates are saved directly.
- **Create a design system from your project.** In a chat with a project folder, choose New design system, then From this project. The agent reads your Tailwind config, CSS variables, theme modules and `DESIGN.md`. DROIDEX parses those files itself, so the document lists the files a kit came from, the tokens it could not map and the values it could not read.
- **Adherence follows the kit.** A frame built under a kit is checked against that kit's own sections: colours, fonts, font sizes, corner radius, spacing and shadows. Findings show on the frame in guide mode and fail the build in strict mode. Auto is never checked.
- **Live previews and covers.** Component previews and demos render with the kit itself, up to four at a time, and show a stored capture when they scroll out of view. A kit's cover appears in the document, the picker and the composer chip, in both light and dark.
- **Kit images.** Add PNG, JPEG or WebP logos, marks and illustrations to a kit's Assets section with the file picker or by dropping them in. Previews and frames built under the kit can use them.
- **DROIDEX ships as a kit.** The DROIDEX preset is now exported from the app, with its notes, primitives, component previews and cover. It shows its bundled captures right away, before any preview renders live. Maintainers update it with `npm run kits:export`.
- **The picker is simpler.** One picker chooses, searches and creates kits: Auto, recent kits, presets and your own, with Open on the current kit. The Manage design systems dialog is gone; Duplicate, Export… and Delete with Undo live in the document's menu.
- **New presets.** Placeholder for the presets slice: describe the rebuilt presets before release.
- **Your v1.6 kits come with you.** Kits saved by v1.6.0 and v1.6.1 open as documents, with their guidance as a note. Frames built under them keep building, and the next save writes the new format.

## What's fixed

- **DROIDEX says why it quit.** The log now ends with one `[lifecycle]` line giving the reason: all windows closed, a Quit from the app menu or the Dock, a relaunch, or another instance already owning the profile. Development builds also log the shutdown signal they received, and each one names its port and profile in its window title and Dock badge, so a Quit sent to the wrong Dock tile is easy to spot.
- **A logged-out Claude Code says how to sign in.** A turn sent to a Claude Code that is not logged in used to end silently. It now fails with "Claude Code is not logged in. Run claude in a terminal to sign in, then send again."
