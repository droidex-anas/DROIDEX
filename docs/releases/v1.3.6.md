## What’s new

- **Tabs across the top.** Keep chats, Projects, Pull Requests and Automations open together. Press ⌘T for a new tab, or choose **Open in new tab** from a chat’s sidebar menu. Drag tabs to reorder them, close one with ⌘W, and reopen the last closed tab with ⌘⇧T. Each chat tab shows its harness mark or a working spinner. The row scrolls when it fills up and keeps the selected tab in view. Once you open a second tab, the chat’s controls sit in the tab row.
- **Up to four chats in one tab.** Drag a sidebar chat onto the edge of a chat to put them beside or above one another, then drag the dividers to resize them. ⌘D adds a new chat to the right and ⌘⇧D adds one below. Each tile has its own conversation and composer; sending, steering, approvals and Stop act on that chat. You can move tiles, swap them by dropping one in the middle of another, and close a tile with ⌘⌥W. Closing a tab or tile leaves the chat in the sidebar. Open tabs and their layouts return when you relaunch.
- **A rebuilt Browser.** Open **Browser** in the utility pane to browse alongside a chat, or expand it to fill the workspace while keeping the composer. **Search or enter address** opens a URL or searches Google for plain words. The toolbar has Back, Forward and Reload, a site icon, a secure-connection mark and a loading bar. **Fit** fills the pane; **Desktop**, **Laptop**, **Tablet** and **Phone** show the page at those sizes. Tablet and Phone also use touch and a mobile user agent. The agent can keep using a page while its pane is closed, its cursor shows where it is acting, and the chat’s Browser card shows a live preview.
- In **Design Mode**, click a component or drag over text to mark what you want changed. A small composer beside the mark lets you describe the change and send it to the chat. Press D to draw over the page, then describe the sketch. Marks and their composer chips share a colour, and **Done** or Esc leaves Design Mode. Agents can also read and act inside page frames, inspect console and network activity, and use developer tools on a site you allow until you quit DROIDEX.
- **Images and code are easier to read.** Open an image to zoom, pan, fit it to the window or **Download** it from the floating controls. The attachment viewer keeps **Crop** beside Download. Code blocks without a language now use the same cards as other code, with Copy, soft wrap and **Show all** for long blocks. Diagrams offer **Expand** to open the full drawing in the image viewer.
- **Projects keep moving when threads report.** A thread’s report wakes the main chat even after you switch away from it, and Claude Code’s own follow-up turns stay part of the conversation. A thread waiting for an answer or your approval no longer stops other projects from receiving reports. If many reports arrive at once, they wait until the main chat can receive them instead of holding the project. A project held because its main chat failed picks up again after that chat’s next successful turn; other holds still use **Resume** in Projects.
- The main chat can now steer a working thread inside its running turn on Droid, Claude Code and Codex. It can choose `steer`, `now` to stop the turn and send next, or `queue` to wait for the turn to finish. It can also give the project and its main chat a short name, then mark the project **Done** with what it achieved once no thread is working or starting and no message is on its way to one. New work reopens it.
- A project’s main chat reads like a group chat: each thread’s report, question or message has that thread’s name and harness mark beside its bubble. The main chat’s last answer shows **Waiting for N threads** while its turn is over and its threads are working; hover to see their names. **Threads** shows the project’s name, a **Running for** timer, the plan’s completed-step count, and the outcome and time taken when it is done. **Needs you**, **Working** and **Recent** each show a count and can be collapsed.
- **Steer reaches Droid natively.** A correction sent with **Steer** joins the running Droid turn at its next step, as it does on Claude Code and Codex. If the turn cannot take it, it waits until the turn ends. A steer stays unread until the harness takes it; you can use **Send now** to interrupt and send it next. Messages from another chat can also steer a working chat.
- **Usage above the composer.** `/usage` shows the current harness’s account limits, how much is used, when they reset and an estimate of whether your current pace lasts until reset. **Refresh** asks again and **Manage usage** opens the account’s usage page. A warning appears when the pace would run a limit out early. A reached limit shows its reset time and, for a model-specific limit, **Switch model**. Droid model switches and limit resets also appear in the conversation. Droid’s account figures need a Factory API key available to DROIDEX; without one, the panel explains that Droid’s own `/limits` still works.
- **Permissions, fast mode and context window in the composer.** Permission modes are **Supervised**, **Auto-accept edits**, **Auto** and **Full access**, with descriptions of what each lets the chat do. Auto-accept edits approves file edits while commands still ask. Claude Code’s Auto uses its own permission classifier when available; otherwise the chat says that approvals still ask. Codex permission changes apply from the next turn, and Droid’s safety checks can still ask in Full access. Claude Code and Codex offer **Fast mode** on supported models, with a reminder that it uses your limits faster. Claude Code also offers **Context window**, with **200k** or **1M** where the model supports it. These are chat preferences and do not change your CLI defaults.
- Questions can offer several selections or a written answer, and approvals show the command, files or tool being requested. Working agents stay visible above the composer while they run. Agent cards show the status, model, task and token figures the harness makes available, and remember when each agent finished. Their conversations, interruptions and error rows survive reopening. A chat waiting for its agents still shows as working and carries on when they finish. Chat switching and streaming do less work in long conversations, and each harness becomes available as soon as its startup check finishes.
- **Smaller installs and update downloads.** The app package includes only the packages needed to run it. The release process now prepares signed delta updates from the last three releases, so a supported update can download the changed parts of the app. Sparkle uses the full download when a delta is unavailable or cannot be used.
- Fixes:
  - Codex chats are told about DROIDEX’s chat, Projects and automation tools, so they can find and use them when asked. That guidance returns when a chat is reopened.
  - Claude Code is detected from its native installation even if its launcher is missing or points to a deleted version.
  - A Droid turn that only thinks and then fails now ends, so you can send again. A failure before Droid takes a steer does not count as its answer.
  - **Send now** waits for the interrupted turn to finish before starting the next prompt, and takes an unread steer before a queued prompt. Stop keeps a withdrawn steer out of the next turn.
  - Commands sent while the app reconnects to its running chats are carried out after recovery instead of being dropped.
  - After the chat connection restarts, model and effort controls return to confirmed settings instead of showing a pending change that can no longer finish.
  - Browser-focused keyboard shortcuts reach DROIDEX, and switching tabs or tiles keeps prompts, questions, approvals and browser pages with the right chat.
  - A closed browser page stops pending actions, a crashed page can be reloaded, and a failed screenshot reports an error instead of waiting indefinitely.
  - Failed Codex MCP servers are named in the chat, and a failed Codex app listing can be tried again.
  - Codex Auto-accept edits checks both ends of a file move and refuses automatic approval outside the workspace or through a symbolic link.
  - Shells, editors and agent processes no longer inherit DROIDEX’s private environment settings.
  - Turning off anonymous usage reporting takes effect even while reporting is still starting.

## Updating from 1.3.5

DROIDEX 1.3.6 keeps the existing application identity, Sparkle signing key,
architecture-specific update feeds, user-data location, session store, settings,
workspaces, automations store, and raw Factory session history unchanged.
Browser cookies and saved passwords keep their existing locations too.

Open tabs and tile layouts are saved in the app’s existing local preferences.
Project start times and completed outcomes are saved in the existing
`projects.json`. Fast mode, context-window choices and the updated permission
meanings are recorded with the existing chat settings and history. No data
needs to be moved.

The default permission mode resets to **Supervised** on this update. Existing
Claude Code chats on Low or Medium become Supervised; existing Codex chats on
Low or Medium become Auto. Droid’s levels stay the same. Off is now called
Supervised and High is Full access. Review each chat’s composer setting and
**Settings → Configuration** before continuing work if you want a different
mode.

Start a new Codex chat to use the updated Projects controls. Codex keeps the
tool definitions a chat received when it started; existing chats keep working
with those tools.

Update checks may run in the background, but DROIDEX does not download or
install updates automatically. Use **DROIDEX → Check for Updates…** or the
update button beside Settings, then approve the update and relaunch.

The macOS artifacts are ad-hoc signed, so a manual DMG install may require
approval in **System Settings → Privacy & Security** on first launch.
