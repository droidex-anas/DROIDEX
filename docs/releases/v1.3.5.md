## What’s new

- **Projects, in beta.** Give one chat a goal and it runs the work as a project. The chat writes a plan and hands the steps that can run at once to threads on Droid, Claude Code or Codex, which report back as they finish. Open **Projects** in the sidebar and choose **New project** to start one in the normal composer, by typing or, on Codex, by voice, or ask a chat to run work in parallel. Every thread is a full chat you can open, steer and stop. Share bugs and ideas with `/feedback` or `/bug` in the composer, or at @anasibnanwar on X.
- The **Threads** tab beside the main chat shows the plan and its threads under **Needs you**, **Working** and **Recent**, and the sidebar’s Projects entry shows when a project needs you. In the chat, each thread is one line you can expand to see its task and live step, and its report arrives as a notice rather than as your message. A thread’s questions come to the main chat, and a desktop notification takes you to a thread that is waiting on an approval.
- A thread starts with the main chat’s folder, harness, model, effort and autonomy unless the main chat picks others, and it never runs above the main chat’s autonomy. Threads can start threads of their own, up to three levels deep. When a second thread would work in the same checkout, it gets its own git worktree on a `thread/<name>` branch; DROIDEX never merges these branches, and **Settings → Worktrees** removes them. Below High autonomy, starting a thread asks first. DROIDEX has to stay open for a project to keep going, and a held project, for example after you stop its main chat, picks up again with **Resume** in Projects.
- **DroidProxy support.** **Settings → DroidProxy** sets up DroidProxy, a separate menu-bar app that serves models from your Claude, Codex, Gemini, Kimi, Junie, Grok and Meta subscriptions to Droid through a local proxy. Thanks to @nikships for this one. On an Apple silicon Mac the page installs DroidProxy, shows whether the proxy is running, and connects Claude Code, Codex, Gemini and Kimi accounts; the others connect in the DroidProxy app. **Apply** backs up `~/.factory/settings.json` and adds the proxy’s models to Factory’s custom models, where Droid’s model picker shows them with the DroidProxy mark. They work in Droid chats while DroidProxy is running.
- **Voice mode on Codex.** On a Codex chat with an empty composer, the orb in place of Send starts a spoken conversation. The voice answers quick questions itself and hands anything that touches the project to the chat’s own agent as an ordinary turn, so autonomy, approvals, diffs and Stop behave as they do for a typed prompt. Both sides stay in the transcript, marked **Spoken**. The conversation docks above the composer, opens full size from the orb, and follows you as a small pill when you leave the chat; only one runs at a time. Voice uses the Codex CLI’s own sign-in (tested with ChatGPT), so there is no API key to set. Choose the voice, and whether it acknowledges briefly or narrates the work, in **Settings → General → Voice**.
- **Fork a chat, or ask on the side.** On Droid, Claude Code and Codex, Fork under a settled answer copies the conversation up to that answer into a new chat, and **Fork chat** in a sidebar row’s menu copies the whole chat. `/btw` or `/side` opens a side chat about the current chat without adding to it, even while the main chat is working, and it can use another harness or model. On the same harness it knows the whole conversation; on another harness a long chat is trimmed to its most recent part. **Send answer to chat** attaches its answer to your next prompt, and **Continue as chat** makes it a normal chat. Side chats open in the side pane or a popup window, as set in **Settings → Configuration → Sessions**.
- **Chats can work with your other chats.** On every harness, you can ask a chat to see what needs you, read or message another chat, answer its question, stop its turn, start a new chat for a task, or settle, reopen and archive chats. Below High autonomy, each of these asks first except reading, and **Always allow** covers only that one chat. Permission requests always wait for you, and a message from another chat arrives as a **Message from** notice, not as your own message. Codex chats also get DROIDEX’s automation tools, which Droid and Claude Code chats already had.
- **Visualizations run inline.** `/visualize` Apps run as soon as they finish, in live replies and in reopened chats, so the Play and Stop buttons are gone. A failed App offers **Auto-fix**, which sends the error and source back to the agent for a new version, and a running App opens **Full screen** from its hover controls. Apps fit narrow chats, follow theme changes, and can load pinned builds of Chart.js, ECharts, D3 and Mermaid, plus Google Fonts.
- Every sidebar row shows its harness mark, Droid included, which turns into the chat’s menu on hover. Activity rows lead with their status and show a working chat’s live activity underneath, workspace rows show a spinner or the linked pull request’s state, and folded sections show a count. Answers get a Copy and Fork row, prompts and answers show their time on hover, and models show their maker’s mark.
- Typing a full `/name` narrows the slash menu to it, and Space turns a named skill or `/visualize` into a chip. Menus, the command palette and sidebar search drop their dividers for a soft selection tint, every command has an icon, and the caret is rounded with a soft blink. The Spec/Chat button is gone (`/spec` still toggles spec mode on Droid and Claude Code), `/mission` is removed, and the palette offers **Pull Requests** in place of Git Status and New Mission. The update button is now a small blue circle beside Settings that opens into an **Update** pill.
- Fixes:
  - A Droid session created in another Factory organization now says which organization it belongs to and asks you to sign Droid in to it, instead of reporting that the session was not found.
  - A chat settled because its pull requests closed can be reopened with **Reopen task**.
  - Activity summaries no longer end in a broken sentence fragment.
  - A Codex request that DROIDEX cannot answer yet is reported in the chat instead of the turn stopping without a word.
  - The app window grants web permissions only to itself, and only for the microphone, clipboard and notifications.

## Updating from 1.3.2

DROIDEX 1.3.5 keeps the existing application identity, Sparkle signing key,
architecture-specific update feeds, user-data location, session store, settings,
workspaces, automations store, and raw Factory session history unchanged.
Projects and forks are recorded in two new files beside them, `projects.json`
and `session-lineage.json`.

The first voice conversation asks macOS for microphone access. If you decline,
allow DROIDEX later in **System Settings → Privacy & Security → Microphone**.
DroidProxy is a separate app, so macOS may ask you to approve its first launch
in **System Settings → Privacy & Security**.

Codex takes DROIDEX’s in-app tools only when a chat starts. Codex chats from
before 1.3.5 keep working without them, so start a new Codex chat to use
Projects, chat tools or automations there. In Claude Code and Codex chats from
before 1.3.5, only the latest answer can be forked.

Update checks may run in the background, but DROIDEX does not download or
install updates automatically. Use **DROIDEX → Check for Updates…** or the
update button beside Settings, then approve the update and relaunch. The native
updater waits for the app and sidecar to settle before installing.

The macOS artifacts are ad-hoc signed, so a manual DMG install may require
approval in **System Settings → Privacy & Security** on first launch.
