## What’s new

- Light mode is easier on the eyes. Every light preset now uses a soft warm off-white instead of stark white, with calmer text and borders. Menus, popovers and dialogs float on a raised surface with a soft shadow instead of hard outlines, and settings dropdowns lose their borders. Dark mode is unchanged.
- The model picker responds immediately. A model or effort change shows on the chip right away and rolls back if the session rejects it. The Droid list is read live from the CLI, including Auto, and a filter separates Droid core models from Factory models.
- DROIDEX now keeps the default model and effort for each harness itself, under **Settings → Configuration → Default models**. It no longer reads or writes the Claude Code or Codex config files. A default saved in 1.3.1 carries over as Droid’s default.
- DROIDEX finds your installed Claude Code and Codex CLIs and keeps them current through the installer that owns each one (Homebrew, npm or the native installer). Updates run once per launch and from **Settings → Setup & updates**. Turn auto-update off there if you prefer.
- Fixes: chats without a folder resume correctly on Claude Code, session files without a start no longer break session discovery, and a lost connection drops pending model changes instead of leaving them stuck.
- Every desktop request from the renderer must now come from the main window, a second lock against other pages or frames reaching the app.

## Updating from 1.3.1

DROIDEX 1.3.2 keeps the existing application identity, Sparkle signing key,
architecture-specific update feeds, user-data location, session store, settings,
workspaces, automations store, and raw Factory session history unchanged.
Cached session summaries rebuild once on first launch. Saved preset themes pick
up the new light colours automatically; custom colours you set yourself are
kept as they are.

Update checks may run in the background, but DROIDEX does not download or
install updates automatically. Use **DROIDEX → Check for Updates…** or the blue
update button beside Settings, then approve the update and relaunch. The native
updater waits for the app and sidecar to settle before installing.

The macOS artifacts are ad-hoc signed, so a manual DMG install may require
approval in **System Settings → Privacy & Security** on first launch.
